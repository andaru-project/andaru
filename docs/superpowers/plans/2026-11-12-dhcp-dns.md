# DHCP and DNS Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A LAN client gets a DHCPv4 lease from Kea, resolves through Unbound (which the firewall uses too), and finds other clients by name; all of it applied, confirmed, rolled back and booted with the network and the filter.

**Architecture:**
- **Declaration:** gains a `dhcp` collection (per served segment) and a `dns` singleton, stored in a new additive `service_changes` table.
- **Rendering:** emits Kea's whole config, an Unbound fragment and a systemd-resolved drop-in as generation files outside `/run/andaru`; the filter gains a fixed DHCP rule.
- **Realizer:** checks the configs with the daemons' own tools before activating, restarts or reloads the daemons after networkd settles, and syncs lease names in a privileged oneshot started by a path unit.

**Tech Stack:** Go 1.27; Debian 13 `kea-dhcp4-server` 2.6.3, `unbound` 1.26.2, systemd 257 (networkd, resolved, path units).

**Spec:** `docs/superpowers/specs/2026-11-12-dhcp-dns-design.md` (approved).

## Global Constraints

- New generation paths, exactly: `/run/andaru-kea/kea-dhcp4.conf`, `/run/andaru-unbound/andaru.conf`, `/run/systemd/resolved.conf.d/50-andaru.conf`. Directories root 0755, files 0644.
- Runtime, not generation: `/run/andaru-leases/leases.conf` (lease names), `/run/kea/andaru-leases-changed` (marker), Kea's socket `/run/kea/kea4.sock`.
- Debian's `/etc/kea/kea-dhcp4.conf` and `/etc/unbound/unbound.conf` are never edited.
- The engine runs no daemon tool and never writes outside its state directory; `realize` does, as root.
- New ID prefix `dhp`. New finding: `DHCP_WITHOUT_DNS` (warning). `TOOL_MISSING` gains the Kea and Unbound cases.
- Kea hooks: `/usr/lib/<multiarch>/kea/hooks/libdhcp_lease_cmds.so` and `libdhcp_run_script.so`, multiarch `x86_64-linux-gnu` or `aarch64-linux-gnu` from `runtime.GOARCH`.
- Names published: `<first label>.<localDomain>`, A and PTR, TTL `valid-lft/3`; default `localDomain` `home.arpa`.

## Rulings (the plan sharpens the spec here)

1. **Storage:** `dhcp` and `dns` versions go in a new `service_changes` table, created `IF NOT EXISTS` on open like `policy_changes`; `changeTable` routes them there.
2. **`dns.segments` may be empty:** Unbound then serves only the firewall. The takeover filters it by kept adapters without having to put DNS servers back on a segment.
3. **Upstreams share one protocol:** Unbound's `forward-tls-upstream` applies to the whole forward zone, so mixed `do53`/`dot` is a validation error at `/dns/upstreams`.
4. **Config checks run in `realize`, not render:** before anything moves, `kea-dhcp4 -t` and `unbound-checkconf` run on the generation's files; a refusal fails the activation like an unverified one. The engine execs no daemon tool, as for nft.
5. **The lease sync reads only the live Kea config:** render puts `"user-context": {"andaru": {"domain": D, "register": B}}` on each `subnet4`, and reservations carry their hostnames. The sync needs no declaration.
6. **The takeover proposes `dns` only when Unbound is installed and `dhcp` only when Kea is,** so a host without them takes over as today instead of failing with `TOOL_MISSING`.

## Review Focus

1. **A client hostname built to inject configuration** (`a"\nlocal-zone: "." redirect`): nothing but a valid label reaches the leases file. Test: Task 5 `TestLeaseNamesRejectUntrustedHostnames`.
2. **An upgraded host whose declaration has neither `dhcp` nor `dns`:** renders no new file, stops no daemon, changes no resolver. Test: Task 3 `TestNoServicesRenderNothingNew`, Task 4 `TestGenerationWithoutServicesTouchesNoDaemon`.
3. **A rollback from a generation with `dhcp` and `dns` to the baseline:** Kea stopped, Andaru's Unbound file and resolved drop-in gone, resolved reloaded. Test: Task 4 `TestRollbackToBaselineStopsServices`.
4. **A lease named like a static lease:** the static lease's address wins. Test: Task 5 `TestStaticNamesWinOverLeases`.
5. **A DHCP range covering the firewall's own address, or a static lease outside the subnet:** refused at save. Test: Task 1 `TestServiceValidation` rows.
